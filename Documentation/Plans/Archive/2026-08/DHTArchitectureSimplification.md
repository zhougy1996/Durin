# DHT Architecture Simplification Plan

Summary: Reduce DurinHeaderTool's code and state surface by deleting obsolete generation paths, consolidating shared generation contracts, splitting parser and writer responsibilities, and moving private manifests into one clean-surviving persistent state system behind stamp-owned build edges.

Last reviewed: 2026-08-13

Status: Archived
Completed: 2026-08-13

## Current Status

Implementation and qualification are complete. DurinHeaderTool now contains
5,698 lines of production Python across 46 cohesive files, down 412 lines from
the 6,110-line baseline. Tests contain 3,288 lines across 12 files, down 638
lines from 3,926; the former 1,678-line reflection test is split by behavior and
the largest resulting test file is 695 lines. `reflection_parser.py` fell from
1,751 to 309 lines and `reflection_source_writer.py` from 636 to 411 lines.

The obsolete definitions path and unused helpers are deleted, module metadata
preparation is deterministic and serial, generated-output naming and strict
codecs have one owner, and reflection workers use one immutable typed result.
Annotation rewriting, property parsing, Clang context, AST assembly, header
writing, source writing, and property emission now have explicit module
boundaries.

Output-owned manifests and per-header persistent entries are replaced by
checksummed schema-v1 `DHTState/export-state.json` and
`DHTState/reflection-state.json` bundles local to each module.
After a purge, the Engine project uses 10 phase files totaling 735,126 bytes
(largest 586,035), versus 140 private manifest/cache files totaling 992,681
bytes in the baseline. Sandbox uses 2 files totaling 34,562 bytes versus 12
files totaling 49,099 bytes. CMake owns stamps and formal generated byproducts
only; clean retained the bundles, purge removed them, and a missing formal
header rematerialized exactly 1/2 CoreDObject headers in 176 ms with zero parse
and a byte-identical digest.

Public outputs are unchanged. CoreDObject, Engine, and Sandbox export SHA-256
values remain `0d6142fd...fafaab`, `c8be86b8...a826bf`, and
`23262f9f...98e62`; their deterministic aggregate generated-C++ hashes remain
`a68a3fc6...488619`, `1db3cf49...677e6`, and `23f322af...77341`.

Serial preparation stayed within the frozen bounds: Engine's final five-sample
median was 492.5 ms (baseline 447.7 ms; limit 497.7 ms) and Sandbox's was
342.1 ms (baseline 361.3 ms); stable samples rewrote zero module files. Warm
ordinary Engine export/reflection took 193/243 ms and Sandbox 179/190 ms, all
with zero parses. Clean/warm-cache generation rematerialized Engine's 56 headers
in 558 ms and Sandbox's 5 in 210 ms with zero parses. A purge produced the
expected cold path: Engine export/reflection parsed 56 headers in 2,099/2,195
ms and Sandbox parsed 5 in 283/325 ms.

Qualification passed with 152 DHT tests, root configure, a cold full `all`
build, the `@reflection` native domain (`CoreObjectTests`,
`CorePropertyChangeTests`, and `CorePropertyValueSnapshotTests`), clean/warm
rebuild, missing-byproduct repair, purge/cold rebuild, and an orderly hidden
DurinEditor eight-tick smoke run. The lasting reflection and build-system
contracts describe the new ownership and recovery model.

## Goal

Make DHT smaller and easier to change without weakening deterministic
generation, incremental behavior, cache recovery, or build integration. The
completed architecture has one owner for generated-output naming, file
fingerprints, exported-symbol serialization, reflection worker results, and
each module phase's reusable state; parser and writer files have cohesive
responsibilities; obsolete paths, duplicate manifest/cache state, and
incidental concurrency are gone.

## Scope

- Remove the unused generated `Definitions.h` implementation, emitted CMake
  variables, path helpers, exports, and tests that exist only for that path.
- Remove unused DHT helpers and collapse the two-value runtime-variant model to
  an immutable, direct lookup.
- Replace threaded module-CMake text generation with deterministic serial
  generation after recording its configure-time baseline.
- Centralize generated output names/paths, file-fingerprint JSON encoding, and
  exported-symbol JSON encoding.
- Replace reflection worker `dict[str, object]` transport and conversion with a
  typed result shared with persistent reflection cache materialization.
- Split annotation rewriting, property/type parsing, Clang parse context, AST
  assembly, generated-header writing, generated-source writing, and property
  source emission into cohesive files while retaining stable entry points.
- Replace output-owned export/reflection manifests plus per-header persistent
  entries with one logical persistent state system containing separate atomic
  export and reflection phase bundles per module.
- Keep stamps as the only custom-command `OUTPUT`s and formal `.export` and
  generated C++ files as `BYPRODUCTS`; remove private state files from CMake
  output ownership and dependency timestamps.
- Standardize persistent phase-state fingerprints on SHA-256 while retaining
  the timestamp/size fast path and deterministic migration from old manifests
  and cache entries.
- Split the monolithic reflection-generation tests by owned behavior and add
  focused deletion, codec, cache, migration, and worker tests.
- Update the lasting reflection and build-system contracts and qualify the
  complete DHT/build integration.

## Non-Goals

- Move `.dproject`/`.dmodule` CMake metadata generation from DHT to
  DurinDevTool, CMake, or a new program.
- Replace DHT's process-global invocation configuration with a repository-wide
  dependency-injection framework or redesign every function signature.
- Implement a complete C++ parser, replace libclang, change the hermetic-header
  contract, or broaden supported reflection syntax.
- Change public `.export` schema v5, reflected qualified identities, generated
  helper names, `.gen.h/.gen.cpp` content contracts, runtime registration, or
  serialization behavior.
- Remove generated-output ownership/damage digests, resolved-symbol dependency
  filtering, atomic publication, or output locks when private manifests move
  into persistent phase state.
- Merge export and reflection into one physical state file or one build command;
  their ordering, invalidation, and failure domains remain distinct.
- Add persistent state files to CMake `OUTPUT`, `BYPRODUCTS`, or `DEPENDS`, or
  use their timestamps to decide whether the build graph runs DHT.
- Solve Ninja/DHT shared CPU budgeting, expose per-header Ninja edges, raise
  worker ceilings, or tune job-pool constants as a substitute for coordination.
- Introduce a general templating framework for short CMake or C++ fragments.
- Fold intrinsic CoreDObject math symbols into normal reflected exports; their
  ownership remains a deferred runtime/DHT contract decision.

## Design Decisions and Invariants

### Compatibility and ownership

- Public export schema v5 and generated C++ are byte-stable inputs/outputs of
  this refactor. Output-owned private manifests are retired; persistent phase
  state receives new schemas and treats old manifests/cache entries as migration
  inputs or typed misses without requiring manual deletion.
- DHT continues to own `prepare_project_build`, project/module CMake metadata,
  export generation, and reflection generation for the duration of this plan.
  A later ownership move requires a separate plan with DurinDevTool and CMake
  consumers in scope.
- Existing CLI command names and required arguments remain stable. Internal
  functions may move, but the CLI and the small parser/writer entry points used
  by tests retain explicit compatibility imports only where a real caller
  exists.
- Module CMake metadata generation becomes serial and remains deterministically
  ordered by module name. Stage 0 records five warm preparation samples; the
  serial path may not regress the median by more than the greater of 10 percent
  or 50 ms on the same worktree/profile.

### Shared domain contracts

- One generated-output naming module owns module source, per-header header/source
  names, absolute paths, and reflected-header basename collision validation.
  Phase state, generators, cleanup, and CMake metadata consume that API.
- `FileFingerprint` owns one strict JSON codec. Timestamp and size are only a
  fast-path guard; SHA-256 is the content identity for newly written private
  phase state. Older MD5 records are accepted only as stale migration input and
  never compared as SHA-256.
- `ExportedSymbolInfo` owns one strict JSON codec reused by public exports,
  persistent export phase state, and migration readers.
  Unknown or malformed generated-state fields remain typed misses/errors rather
  than being silently discarded.
- Reflection workers and persistent-cache hits return the same typed immutable
  header-generation result. No intermediate string-keyed result dictionary or
  bidirectional conversion layer remains.

### Parser and writer boundaries

- Annotation rewriting owns marker discovery, payload validation, source-line
  preservation, and DMETA use tracking; it does not own Clang traversal or
  reflected-property construction.
- Property parsing owns source/AST type spelling, containers, object wrappers,
  intrinsic aliases, namespace-aware resolution checks, layout expressions,
  and property metadata. Clang session setup and top-level class/struct/enum AST
  assembly remain outside it.
- Clang context owns parser arguments, the synthetic prelude, translation-unit
  creation, and preprocessor-context validation. The reflection parser remains
  the orchestration entry point that assembles `ReflectedHeaderInfo`.
- Header, source, and property writers may share a minimal line builder and
  naming helpers, but generated text ordering and whitespace remain byte stable.
  File splitting is not permission to redesign the generated C++ contract.

### Cache and publication

- `<Module>/DHTState/export-state.json` and `reflection-state.json` are the
  selected logical store. They are separate atomic phase bundles because export
  and reflection are separate ordered commands with different inputs and
  failure domains; sharing a cache root and storage implementation does not
  require sharing one physical file.
- Export state owns current input/context identity, dependency-export digests,
  per-header fingerprints and raw symbol projections, and the resolved public
  export digest. Reflection state owns current input/context identity,
  per-header generated text/counts/dependency snapshots, complete output
  ownership, output digests, and pending cleanup state.
- Persistent state is reconstruction data, never a compiler input or build-graph
  output. CMake does not list it in `OUTPUT`, `BYPRODUCTS`, or `DEPENDS`; project
  purge may delete it, while ordinary clean must not.
- Export and reflection stamps remain the custom-command `OUTPUT`s. Reflected
  headers, module metadata, tool fingerprint, and dependency exports remain the
  real `DEPENDS`; formal `.export` and generated C++ files remain `BYPRODUCTS`
  and direct dependencies of the module DHT target so a missing formal output
  reruns the command even when its stamp exists.
- A completely current command validates one phase bundle and skips. A changed
  header reuses unaffected records from the same bundle. After clean removes
  formal outputs and stamps, DHT rematerializes all outputs from the surviving
  bundle with zero parser calls. An invalid bundle is a typed module-state miss;
  a valid bundle with an invalid per-header record reparses only that header.
- Phase bundles use canonical checksummed JSON, compare-before-write, atomic
  replacement, and the existing module lock. Updating a bundle never touches a
  build stamp; CMake touches the stamp only after DHT exits successfully.
- Formal outputs publish atomically before successful command completion. If
  phase-state publication fails after an output write, the command fails before
  the stamp is touched and the next invocation repairs state; a cache file is
  never required for correctness.
- Warm ordinary incrementality and warm clean-output rematerialization may not
  regress their Stage 0 medians by more than the greater of 10 percent or 100 ms
  on the same module/profile. Bundle packaging must be revisited in Stage 4 if
  whole-bundle validation or atomic rewriting violates either bound.
- Generated-output damage repair, stale-output cleanup, pending cleanup
  ownership, and module/project locking remain deterministic when their state
  moves out of CMake-owned manifests.

## Current Foundations and Gaps

| Area | Existing foundation | Gap owned by this plan |
| --- | --- | --- |
| Definitions generation | Runtime modules own explicit `*API.h` headers and no production caller invokes DHT's definitions generator. | Dead generator, path helper, and emitted unused CMake variables remain. |
| Runtime variants | Only `DurinEditor` and `DurinGame` are supported and consumers need an editor boolean. | A dataclass, built-in registry, and per-project cache duplicate two immutable values. |
| CMake metadata | Module content is deterministic and compare-before-write. | A thread pool and preload protocol wrap small string-generation tasks. |
| Output naming | Flat per-module generated names and unique basenames are established contracts. | Manifest, reflection generator, and CMake generator construct names independently. |
| Generated-state codecs | Strict schema-backed descriptor parsing and canonical persistent cache validation exist. | Fingerprint and exported-symbol JSON logic is repeated across output manifest and cache models. |
| Reflection workers | `ReflectionHeaderCachePayload` already models generated text, counts, and dependencies. | Workers return untyped dictionaries that are converted to and from the same payload shape. |
| Parser | Hermetic source transformation, scoped resolution, AST/source agreement, and deterministic diagnostics are qualified. | Annotation, type-system, Clang-session, and AST-assembly changes share a 1,751-line file. |
| Writer | Generated C++ is deterministic and covered by extensive golden assertions. | Header, class, struct, enum, property, and module source writing share one file and two large orchestration functions. |
| Build graph | Export/reflection stamps are primary outputs; formal generated files and private manifests are byproducts; real source/tool/export inputs are dependencies. | Private reconstruction state is unnecessarily CMake-owned even though a second unowned cache already proves clean-surviving recovery. |
| Export incrementality | Output manifest raw projections accelerate ordinary rebuilds; persistent entries rematerialize after clean. | Two storage envelopes own the same logical state and require an L1-to-L2 fallback path. |
| Reflection incrementality | Output manifest owns fingerprints, dependency filtering, output ownership, and cleanup; persistent entries own generated content and the same dependency snapshots. | Ordinary incrementality and clean recovery are split across duplicate state paths. |
| Fingerprints | Timestamp/size avoid unnecessary content hashing; SHA-256 already protects persistent entries and generated outputs. | Output manifests retain a separate MD5 content-identity path and duplicate codecs. |
| Tests | Complete DHT coverage qualified recent schema, cache, and namespace work. | Reflection behavior is concentrated in a 1,682-line test file and deletion boundaries are not explicit. |

## Definition of Done

- The obsolete definitions path, confirmed unused helpers, redundant runtime
  variant caches, and incidental module-CMake thread pool are removed.
- Generated output naming, file fingerprints, exported-symbol codecs,
  generation context, and reflection worker results each have one owner.
- Parser, writer, and reflection tests are split along the recorded semantic
  boundaries without generated-byte or diagnostic drift.
- Output-owned private manifests and per-header persistent entries are replaced
  by one logical clean-surviving state system with separate atomic export and
  reflection phase bundles.
- CMake/Ninja own only phase stamps and formal generated byproducts; persistent
  state has no build-graph timestamp role, clean retains it, purge removes it,
  and missing formal outputs still trigger DHT.
- Public export v5, generated C++, reflected identities, registration,
  serialization, atomic publication, locks, and recovery behavior remain
  compatible.
- Preparation, one-header incremental, and clean-rematerialization timings
  remain within their frozen bounds; final code line count and cache file count
  are lower than the Stage 0 baseline, while byte-size changes and atomic bundle
  rewrite costs are measured and explained.
- Complete DHT, configure/generation, full-build, native reflection/runtime,
  runtime-smoke, and documentation qualification passes, and lasting behavior
  is documented outside this plan.

## Deferred Follow-ups

- Move project/module CMake metadata generation from DHT to DurinDevTool, CMake,
  or a dedicated build-metadata program.
- Replace process-global config registries with an explicit invocation context
  if future multi-project workers or in-process repeated invocations require it.
- Represent CoreDObject intrinsic math symbols through a runtime-owned export
  catalog instead of DHT resolver constants.
- Coordinate Ninja and DHT parser children through a shared jobserver or
  Ninja-visible header/shard edges as tracked by the existing investigation.
- Redesign the qualified helper-name scheme to permit underscores in reflected
  namespace/type segments.
- Generalize generated C++ templating only if additional writers demonstrate
  repeated structural demand.
- Replace JSON phase bundles with an indexed store only if Stage 4 evidence
  shows bounded module bundles cannot meet the recorded incremental/rewrite
  limits; do not adopt SQLite or another storage engine preemptively.
