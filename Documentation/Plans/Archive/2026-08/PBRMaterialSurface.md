# PBR Material Surface Plan

Summary: Replace the fixed Blinn-Phong material slice with a validated metallic/roughness PBR surface contract.

Last reviewed: 2026-08-05

Status: Archived
Completed: 2026-08-05

## Current Status

Stages 0-5 are complete. For integration, the incremental stage commits were
rebased and squashed onto `dev` baseline
`63453303d5078e8b9bafdfd9455ccc14b3b8e937`; the implementation and closure
documentation land together in the PBR integration commit containing this plan
state. The handoffs below preserve each stage's working set, decisions, and
validation rather than intermediate commit identities.

The StaticMesh surface now compiles the canonical metallic/roughness schema
into the immutable v2 `FMaterialRenderRepresentation` and consumes it only
through `FMaterialRenderV2Binding`. Eight usage-validated texture roles have
independent UV0-UV3 transforms and role-specific fallbacks. Tangent-space RNM
normal composition, mirrored-transform handedness, Cook-Torrance GGX direct
lighting, and split-sum studio environment lighting are shared by level,
Material Preview, and thumbnail output.

The studio environment is a hidden Engine asset generated by the independent
`EnvironmentLightingBake` tool. `DEnvironmentLighting` validates its checked-in
payload and cooks directly to the generic package bulk companion without DDC;
editor startup loads the asset instead of generating approximately 47 million
IBL samples. Runtime material, texture, shader-parameter, StaticMesh, viewport,
and roadmap documents now own the lasting contracts and limitations. The
fixed opaque pass still carries Opacity only as output alpha and ignores
OpacityMask for coverage/depth; render-pass behavior remains a future,
separately selected milestone.

## Goal

Define and implement an initial metallic/roughness PBR surface for StaticMesh
materials with constant and texture-backed base color, normal, metallic,
roughness, ambient occlusion, emissive, opacity, and opacity-mask inputs;
correct color space and fallback behavior; tangent-space normal mapping;
per-input UV channel
selection and basic UV transform; and a selected environment-lighting baseline.

The result must be authorable through the schema-driven material domain,
render consistently in level viewports, previews, and thumbnails, and remain a
bounded surface-contract step rather than a material compiler or render-pass
rewrite.

## Scope

- Select exact PBR parameter identities, types, ranges, defaults, grouping,
  texture-usage hints, UV selection, and transform semantics.
- Define a linear metallic/roughness workflow and energy-conserving direct-light
  response.
- Add constant and texture-backed base color, tangent-space normal, metallic,
  roughness, ambient occlusion, emissive, opacity, and opacity-mask inputs.
- Use Color/sRGB sampling for base color and emissive and linear data sampling
  for normal, metallic, roughness, ambient occlusion, opacity, and opacity mask.
- Decode tangent-space normals with the existing packed tangent basis and
  mirrored-transform handedness.
- Support UV channels available from the local vertex factory, defaulting to
  UV0, with validated scale and offset per texture-backed input.
- Select and implement an initial environment-lighting baseline sufficient to
  judge roughness, metallic response, normals, and emissive consistently.
- Preserve material inheritance, stable proxy updates, texture readiness and
  fallback, thumbnails, previews, and shader/resource recovery.
- Define and test compatibility behavior for the existing BaseColor,
  BaseColorTexture, Opacity, SpecularStrength, and Shininess schema.

## Non-Goals

- Actual opaque, masked, or translucent pass policy; alpha blending, mask
  discard, culling, depth-write selection, translucent sorting, depth-only, or
  shadow-depth passes.
- Deferred shading, a GBuffer, clustered lighting, multiple light types, shadow
  maps, or a general lighting architecture rewrite.
- A material graph, arbitrary expressions, generated shader source/IR,
  material functions, or asynchronous compilation.
- Advanced lobes such as clear coat, sheen, subsurface, anisotropy,
  transmission, refraction, iridescence, or displacement.
- Per-material sampler assets, virtual textures, texture streaming, or generic
  texture dimensions.
- Dynamic gameplay material instances or performance-driven draw-command,
  descriptor, or uniform caching.

## Design Decisions and Invariants

- The surface model uses a metallic/roughness workflow. Metallic, roughness,
  ambient occlusion, opacity, and opacity mask are scalar linear inputs; base
  color and emissive are linear values authored or sampled with Color/sRGB intent;
  tangent-space normals are linear data.
- Base color, normal, metallic, roughness, ambient occlusion, emissive, opacity,
  and opacity mask receive stable parameter GUIDs. Renames or editor regrouping
  do not change persistent identity.
- Every input has a deterministic constant and texture fallback. Missing,
  unloaded, failed, replaced, or destroyed textures must not change descriptor
  shape or expose an invalid RHI resource.
- Normal decoding uses the established tangent `xyz`, handedness `w`, and local
  transform determinant sign. Missing normal data resolves to a flat normal.
- UV channel indices are validated against the supported vertex-factory range.
  Missing requested channels resolve by the Stage 0 selected fallback; they
  never read outside the vertex payload.
- Dynamic surface values and texture choices do not create shader
  permutations. Only static properties selected by the material shader-map
  contract may affect shader identity.
- Opacity and opacity-mask values are produced by the surface contract, but
  actual coverage, blending, sorting, and depth behavior remain owned by the
  later Material Render Pass plan.
- Renderer consumes only the completed versioned material render
  representation through its selected binding contract. It does not read
  reflected definitions, fixed public material fields, or resolve GUIDs and
  names per draw.
- Level rendering, material preview, and thumbnails use the same surface shader
  and fallback semantics; preview-specific lighting may differ only through an
  explicit view/environment input.
- Existing materials receive selected, deterministic compatibility behavior.
  Silent coincidental remapping by collection order is forbidden.

## Current Foundations and Gaps

### Foundations

- StaticMesh vertices provide position, color, normal, tangent handedness, and
  up to four UV channels through `FLocalVertexFactory`.
- Texture build settings provide Color, Normal, and Data/Mask usage, explicit
  sRGB policy, usage-appropriate mip filters, BC formats, DDC restoration, and
  counted texture-reference publication.
- Renderer owns white, black, and flat-normal defaults and a shared
  linear-repeat sampler.
- Material declarations provide stable GUID, type, default value, presentation
  metadata, range, and texture-usage hint.
- Material instances inherit values and publish changes through stable proxies
  without scene-proxy recreation.
- StaticMesh shader and pipeline identities already distinguish static material
  properties even though most policies remain visually fixed. The v1 layout
  identity is separate from those static properties and must not be mutated in
  place when PBR inputs are added.

### Gaps

- The current shader implements Blinn-Phong rather than a metallic/roughness
  BRDF.
- Only base color has a texture-backed renderer binding; normal and data texture
  usages are not consumed by materials.
- There is no selected environment-lighting contract for assessing metallic
  reflection and roughness.
- UV choice and transform are not material inputs; the shader always uses UV0.
- Existing `SpecularStrength` and `Shininess` parameters remain in v1 with
  their current Blinn-Phong meaning; the PBR plan must explicitly choose a
  migration/default rule rather than silently reinterpret them as metallic or
  roughness.
- Rendered-image coverage does not yet validate PBR constants, texture roles,
  color-space behavior, tangent normals, mirrored transforms, or fallback
  substitution.

### Render Layout V2

The PBR representation uses layout version 2 and exact identity
`308cda9d-46b94861-b65088db-c84e7feb`. V1 remains immutable and its factory,
validator, binding decoder, and tests remain available; it is never changed in
place. Runtime representations are transient, so current materials compile
directly to v2 and Renderer consumes only a new exact v2 binding. A v1 or any
malformed snapshot reaching the v2 draw path produces one `ShaderBinding`
diagnostic and selects the complete v2 fallback before shader-map and pipeline
lookup.

V2 has a 352-byte, 16-byte-aligned uniform payload, 32 uniform fields, and
eight counted Texture2D resource fields. Compact uniform indices follow this
exact order:

- BaseColor Vector3 at 0, Opacity Scalar at 12, Emissive Vector3 at 16,
  Metallic Scalar at 28, Normal Vector3 at 32, Roughness Scalar at 44,
  AmbientOcclusion Scalar at 48, and OpacityMask Scalar at 52.
- The eight UV-channel Scalars occupy offsets 64 through 92 in texture-role
  order.
- The eight UV-scale Vector3 fields occupy offsets 96 through 208 at 16-byte
  strides; the eight UV-offset Vector3 fields occupy offsets 224 through 336
  at 16-byte strides.
- Bytes 56-63 and every fourth component after a UV Vector3 are zero padding.
  Resource compact indices 0-7 follow texture-role order.

The v2 fallback uses the schema defaults, null counted references, white for
BaseColor and every scalar role, flat normal for Normal, and black for
Emissive. Dynamic bytes and resource identities remain excluded from shader
and pipeline identity. Adding, removing, retyping, or reordering any v2 field
requires a new layout identity rather than editing this table.

### Surface Composition and Sampling

- `uv = selectedUV * scale.xy + offset.xy`; the shared material sampler remains
  linear-repeat with the texture mip chain. UV indices never exceed 3.
  StaticMesh build data continues to record its source-channel count but fills
  every absent vertex payload channel with UV0 (or `(0, 0)` when UV0 is absent),
  so a requested unavailable channel deterministically samples UV0 without a
  vertex-factory expansion or out-of-range access.
- Effective BaseColor is clamped constant RGB times sRGB-decoded texture RGB
  times linear vertex-color RGB. BaseColorTexture alpha is ignored. Effective
  Metallic, Roughness, AO, Opacity, and OpacityMask are their clamped constants
  times the fixed linear texture R channel. No channel selector or packed-map
  convention is part of v2.
- Effective Emissive is the non-negative constant plus sRGB-decoded texture
  RGB; its black fallback therefore preserves the constant. It is scene-linear
  radiance with no physical-unit conversion and is added after all lighting.
- A normal texture decodes linear BC5/RG as `xy = rg * 2 - 1`; oversize `xy` is
  normalized, and positive `z = sqrt(max(1 - dot(xy, xy), 0))` is reconstructed.
  The normalized constant tangent normal and decoded texture normal combine
  with reoriented normal mapping (RNM), so either flat input preserves the
  other. A non-finite or near-zero result becomes `(0, 0, 1)`.
- TBN uses normalized world normal `N`, Gram-Schmidt world tangent `T`, and
  `B = cross(N, T) * tangent.w * determinantSign`. Degenerate TBN input falls
  back to the geometric world normal. Vertex alpha multiplies Opacity only.
- Lit output alpha is effective Opacity. OpacityMask is carried and evaluated
  by the surface helper but does not alter color, alpha, coverage, or depth in
  this plan. Unlit output is effective BaseColor plus Emissive with the same
  alpha; it bypasses direct light, environment, normal, metallic, roughness,
  and AO.

### Direct-Light BRDF and Output

Lit shading uses one unattenuated directional radiance input and the
Cook-Torrance metallic/roughness model below. All dot products are saturated;
safe normalization uses a `1e-8` squared-length threshold; divisors use a
`1e-5` floor; perceptual roughness is clamped to `[0.045, 1]` for evaluation.

- `alpha = roughness^2`, `alpha2 = alpha^2`.
- `D = alpha2 / (PI * (NoH^2 * (alpha2 - 1) + 1)^2)` (GGX/Trowbridge-Reitz).
- `Vis = 0.5 / (NoL * sqrt(NoV^2 * (1 - alpha2) + alpha2) + NoV *
  sqrt(NoL^2 * (1 - alpha2) + alpha2))` (height-correlated Smith GGX).
- `F0 = lerp(0.04, BaseColor, Metallic)` and
  `F = F0 + (1 - F0) * (1 - VoH)^5` (Schlick).
- `Diffuse = (1 - F) * (1 - Metallic) * BaseColor / PI` and
  `Direct = (Diffuse + D * Vis * F) * LightRadiance * NoL`.

The old scalar ambient and preview rim terms are removed. AO never affects
direct light or Emissive. RGB output is finite, scene-linear, and unclamped;
there is no exposure, tone mapping, or output transfer function in this plan,
so an UNORM render target clips on store. Emissive is added after direct and
environment light. Under aligned unit white light, BaseColor `(0.5, 0.5, 0.5)`,
Metallic `0`, Roughness `0.5` produces RGB
`(0.20371833, 0.20371833, 0.20371833)`; BaseColor `(0.8, 0.2, 0.1)`, Metallic
`1`, Roughness `0.5` produces `(1.01859164, 0.25464791, 0.12732395)`.

### Deterministic Environment Baseline

Renderer owns one generated studio environment shared by level, preview, and
thumbnail views. It is not a material parameter or content asset and does not
follow a scene SkyBox. Its source radiance for normalized direction `d` is:

`lerp((0.025, 0.020, 0.018), (0.18, 0.28, 0.50), saturate(d.z * 0.5 + 0.5))`
`+ 6 * (1.0, 0.78, 0.55) * pow(saturate(dot(d,
normalize((-0.4, 0.5, 0.75)))), 256)`.

Renderer deterministically generates a 16x16 RGBA16F cosine-convolved
irradiance cube, a 64x64 RGBA16F GGX-prefiltered cube with seven mips mapped by
`roughness = mip / 6`, and a 128x128 RGBA16F split-sum BRDF LUT. Generation
uses the engine TextureCube direction convention, Hammersley sampling, 1024
samples per output for irradiance and LUT, and 1024 samples at specular mip 0
halving to a floor of 64 for later mips. Resources use one Renderer-owned
linear-clamp/trilinear sampler and the established generation/invalidation,
stale-ready, multi-view, device-retry, render-thread release, and shutdown
contracts.

For environment diffuse, `F_ibl = F0 + (max(1 - Roughness, F0) - F0) *
(1 - NoV)^5`. The diffuse term is `Irradiance(N) * BaseColor / PI *
(1 - F_ibl) * (1 - Metallic)`; environment specular is
`Prefilter(R, Roughness) * (F0 * Lut.x + Lut.y)`. Effective AO multiplies both
environment terms and nothing else. If any environment generation or binding
is unavailable, the whole environment set resolves to Renderer-owned black
cube/LUT fallbacks, yielding zero environment while direct light and Emissive
remain valid. No old scalar ambient survives, so energy is not double-counted.

### Compatibility and Frozen References

Schema-v1 packages upgrade deterministically by creating the canonical v2
definition set and copying existing BaseColor, BaseColorTexture, and Opacity
values and overrides by GUID. Removed base-material SpecularStrength and
Shininess values are discarded with one upgrade warning; removed instance
overrides remain serialized explicit orphans under the existing orphan rule.
Neither enters v2 render data or is reinterpreted because no lossless mapping
to Metallic/Roughness exists. New inputs receive the defaults above.
BaseColorTexture RGB, vertex-color RGB, Opacity, inheritance, and proxy behavior
are preserved; BaseColorTexture alpha no longer multiplies output alpha, which
has no visible effect in the current fixed opaque pass and is recorded for the
later render-pass migration.

The following CPU and rendered references are frozen before implementation:

| Reference | Fixed input and required observation |
| --- | --- |
| BRDF CPU | The two aligned-light values above; Roughness `1` dielectric gray produces `0.15597184` per channel; all validated extremes remain finite. |
| Color space | An sRGB texel `0.5` reaches the shader as `0.21404114`; the same Data/Mask texel remains `0.5`. |
| Channels/fallback | Data texel RGBA `(0.25, 0.75, 1, 0.5)` contributes `0.25`; null/not-ready/failed/replaced/destroyed roles match their white, black, or flat-normal fallback without descriptor-count change. |
| Material sphere grid | Orange fallback plus gray dielectric and red-metal rows at Metallic `0/1`, Roughness `0.045/0.25/0.5/1`, under fixed direct and generated environment light; highlights narrow monotonically as roughness decreases and metals have no diffuse lobe. |
| Normals/mirrors | Flat, tangent `+X`, and tangent `+Y` normal patches on ordinary and negative-determinant paired meshes; the paired world-space perturbations agree after the mirrored geometry transform and detect either handedness sign error. |
| UV and roles | A four-channel UV mesh assigns distinct quadrant patterns to UV0-UV3 and uses scale `(2, -1)` plus offset `(0.25, 0.5)` per role; a one-channel copy requested at UV3 exactly matches UV0. Each texture role changes only its defined input. |
| AO/emissive/alpha | AO `0` removes indirect light only; Emissive is invariant under light/environment absence; Opacity changes output alpha, while OpacityMask alone changes neither the current color nor coverage. |
| Surface parity | The same material, camera, direct-light values, and environment identity render matching central regions in level viewport, Material Preview, and thumbnail captures; explicit view framing is the only permitted difference. |

Rendered references use fixed 256x256 RGBA8 captures, the shared preview sphere
and split-attribute test mesh, fixed camera matrices, and pixel tolerance of two
UNORM codes except BC-compressed normal/color samples, which use four. The
capture fixtures and approved pixel hashes land with the first stage that can
produce each output; Stage 0 freezes their inputs and acceptance ordering rather
than manufacturing pre-implementation golden images.
